# 京台科技项目承诺账

保存科技合作从**接洽、签约、资源投入、验证完成到订单形成**五个阶段的证据关系，
为京台科技项目专员提供承诺管理后台。核心目标：让论坛复盘的每个数字都能下钻核实，
“交换过名片”不能被包装成合作成果。

所有样例主体、档案编号与材料均为**虚构数据**，不含真实个人信息或凭据。

## 记账口径（复盘统计不可绕过的四条规则）

1. 五个阶段**分开统计**：接洽 / 签约 / 资源投入 / 验证完成 / 订单形成。
2. 只有 **当前有效版本（active）+ 专员核验成立 + 强证据齐备 + 前置阶段满足** 的里程碑才计入数字；
   被替代版本不计入，撤回项目单列、不混入成果。
3. **名片等弱凭证永不单独计入接洽**，进入“弱凭证剔除清单”。
4. 同一项目（`projectKey` 归一化去重）同一阶段只计一次，重复登记不会翻倍。

每个数字都可下钻到：**责任主体、适用范围、前置条件（含是否满足）、逐条证据（含证据是否足以支撑该阶段）、核验时间、对应承诺**。

## 承诺生命周期

- **六类管理对象**：台企能力（capabilities）、北京科研资源（resources）、场景需求（needs）、
  尽调材料（materials）、签约/意向版本（intents，含承诺清单 commitments）、里程碑（milestones）。
- **只有各方确认完整的意向才能进入执行**：所有参与方逐一确认同一内容指纹（SHA-256），
  且尽调清单全部到齐，意向才从 `draft` 激活为 `active`。
- **重复项目不产生两个有效版本**：同一项目键已有 `active` 版本时，重复登记直接 409 拒绝；
  变更必须走“新版本登记”，旧版转 `superseded`。
- **撤回只终止后续动作**：意向转 `withdrawn`，未完成里程碑终止；已发生的接洽、签约等事实保留并在复盘单列。
- **版本变化明确影响哪些未完成承诺**：旧版未完成里程碑逐条挂起（`blocked`）并标注受哪个新版本影响，
  材料随版归档复制（密级与授权范围不变），需在新版重新确认。
- **商业秘密按参与方隔离**：`secret` 材料仅所有方与显式授权参与方可见；
  非参与方看不到本体，专员只见元数据、正文引用遮蔽；授权给非参与方会被拒绝。

## 目录结构

```
contracts/context.schema.json   领域资料格式（原有）
contracts/report.schema.json    复盘报告 JSON 契约
fixtures/context.json           领域事实样例（原有）
src/catalog.js                  合作类别/角色/五阶段/证据类型等领域词汇
src/seed.js                     四类产业虚构样例项目
src/store.js                    存储、激活锁、商业秘密可见性
src/hashing.js                  意向正文内容指纹
src/service.js                  登记/确认/激活/撤回/改版/证据核验
src/review.js                   五阶段分账、下钻、项目时间线、弱凭证剔除
src/server.js                   零依赖 HTTP 接口 + 单页后台
public/admin.html               管理后台页面（无第三方库）
test/                           node:test 测试（28 项）
```

## 本地运行

```bash
npm start          # http://localhost:8080 （PORT 环境变量可改端口）
npm test           # node:test，28 项测试
```

后台页顶部可切换查看身份，以验证商业秘密隔离；漏斗与产业标签点击后下钻明细表。

## 主要 HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/report` | 完整复盘报告：五阶段计数+下钻、产业分解、项目时间线、弱凭证剔除、撤回项目 |
| GET | `/api/catalog` | 类别/角色/阶段/证据类型目录 |
| GET | `/api/parties` `/api/assets` | 参与方与能力/资源/需求/里程碑 |
| GET | `/api/intents?viewerPartyId=` | 意向列表（材料随查看身份隔离） |
| POST | `/api/intents` | 登记意向（重复 active 项目返回 409） |
| POST | `/api/intents/:id/confirm` | 参与方确认（可带客户端内容指纹比对） |
| POST | `/api/intents/:id/withdraw` | 撤回（仅终止后续动作） |
| POST | `/api/intents/:id/new-version` | 登记新版本，返回受影响的未完成里程碑 |
| POST | `/api/materials` | 提交尽调材料（secret 需给授权参与方） |
| POST | `/api/milestones` | 登记里程碑（阶段、责任主体、适用范围、前置条件） |
| POST | `/api/milestones/:id/evidence` | 提交证据（名片自动标注为弱凭证） |
| POST | `/api/milestones/:id/verify` | 专员核验成立 |
| GET | `/api/audit` | 审计流水 |

代码库只负责按上述标识与版本约定记账与核验，不替代线下签署与合规审查。
